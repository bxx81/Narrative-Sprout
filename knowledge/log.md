# Knowledge Bundle Update Log

## 2026-09-27
* **Fix**: Long-press copy on a choice button can no longer swallow the next ordinary click. `GameChoices.tsx` moved from `mouse*`/`touch*` handlers to a Pointer Events state machine: `pointerdown` (primary button only) records the pointer id + press origin and **clears** `suppressNextClickRef` (renamed `longPressTriggered`), a wander past the new `LongPressMoveSlopPx` (10 px) or `pointerup`/`pointercancel`/`pointerleave` ends the press, and the timer callback sets the latch so the trailing `click` is swallowed exactly once in `onClick`. The old latch lived only inside `onClick`, so a long press that ended without a `click` reaching the button — mouse released off the button (the click lands on the common ancestor, `MAIN`), or a finger that drifted before lift-off (the browser drops the synthesized mouse/click events entirely) — left it set and ate one later click. An unmount cleanup clears the pending timer; the overwrite-at-`pointerdown` reset doubles as self-healing for a pointer id that never saw its `pointerup`. Accepted edge: keyboard Enter immediately after a long press loses one submission.
* **Addition**: Copy-to-form is announced — new i18n key `toastChoiceCopied` in all 5 locales (279 → 280 keys each) plus `toast.success(...)` in the `GameChoices` long-press timer and in `GameScreen`'s choice-echo timers, which now share the extracted `applyChoiceEchoPreset()` (1000 ms mouse / 500 ms touch). The `choicePreset` apply effect in `GameChoices` deliberately stays silent, otherwise one gesture would toast twice; `ToastSoundPlayer` plays `notification.ogg` for the new toast as it does for every other. Documented in `features/game-loop.md` (new Long-press copy bullet).
* **Testing**: New `e2e/longpress.spec.ts` (5 cases: mouse release-on-button, mouse release-off-button, choice echo, touch long press, touch + finger drift) and the shared `e2e/helpers/story.ts` `startStory()` helper (also migrated `playthrough.spec.ts` off its inline flow). Mutation check: removing only the `pointerdown` latch-clear makes exactly the release-off-button and touch-drift cases fail, the other three keep passing. Both touch cases hold the pointer through CDP `Input.dispatchTouchEvent` because Playwright's `tap({ delay })` awaits the delay *before* the tap (its Chromium delegate sends `touchStart`/`touchEnd` back to back), so they are chromium-only — WebKit keeps the three mouse cases. E2E total: 7 spec files / 42 tests (39 pass + 3 engine-gated skips); unit suite unchanged at 336.
* **Correction**: stale knowledge counts — key totals in `configuration/localization.md` and `features/settings-system.md` (279 → 280), `references/asset-inventory.md` was doubly stale (327 keys and locale file sizes that no longer match disk → 280 keys + measured KB), `operations/testing.md` (49 unit files / 263 tests → 64 / 336; 5 e2e specs / 30 tests → 7 / 42), and its spec table + helper list now cover `longpress.spec.ts`, `sample.spec.ts`, and `story.ts`.

## 2026-09-26
* **Change**: Scene-image generation failures no longer return a "Image Generation Failed" SVG — `generateSceneImage` rethrows (non-abort), so the turn stores **no asset**, i.e. exactly the Disabled-backend state: transparent placeholder on the game screen, "Image Not Available" on the card screens. Reporting goes through the new `TurnServiceOptions.onImageGenerationFailed` → `notifyImageGenerationFailure` toast (`imageGenerationFailedToast` + classified reason, fixed id `image-generation-failed` so autoplay cannot stack toasts); user Stop stays silent. Image *regeneration* failures keep the retryable `ErrorDialog`. Documented in `features/image-generation.md` (new Failure handling section), `integrations/image-generators.md`, `services/error-service.md`, `features/game-loop.md`, `features/history-and-saves.md`.
* **Change**: Card thumbnails unify on `LOAD_SCREEN_FALLBACK_URL`: the shared `applyLoadScreenFallback` (`<img onError>`) now lives in `imageFallbacks.ts` and is wired inside `StoryCard` (LoadScreen's private handler removed) and `ChronicleScreen`, so an asset that exists but fails to decode renders "Image Not Available" everywhere instead of a broken image.
* **Change**: Settings can no longer be edited blindly during a long operation — `SettingsScreen` computes `isBusy` from `generation` / `imageRegeneration` / `autoplayTurn` / `uiTranslation` and locks the Image Generation section (generator `<select>` + every backend panel), mirroring `ThemeSetupScreen`'s `loading` guard; `updateSettings` additionally drops an unrecognized `textModel` (`parseTextModelOptions`) with a console warning while still applying the other fields, so the debounced input write cannot persist a model the narrator cannot parse. Documented in `features/settings-system.md` (new Editing While Generating section).
* **Change**: A failed autoplay decision is no longer a silent stop — `ErrorDialog` now watches `autoplayTurn` and shows the failure `onlyInformation` (Dismiss only: there is no decision payload for `retryGeneration` and `autoplay` is already off, so the user re-enables it manually). `dismissError()` returns `autoplayTurn` to `idle` as well; a decision-phase `AbortError` still settles silently. Documented in `services/error-service.md`, `features/autoplay.md`, `data-model/state-management.md`.
* **Addition**: AI translation is cancellable — new `cancelUiTranslation()` action aborts the store-module `uiTranslationAbortController` (its `signal` reaches `translateService`), settles `uiTranslation` to `idle` immediately, and is surfaced as a stop button in `Settings > Display` (`aiTranslationCancelButton`, all 5 locales). A cancelled or superseded run persists nothing and cannot rewrite `language`: `translationLanguageActivation(startedSettings, currentSettings, languageName)` returns the new `{ uiLanguage, language }` only while the user has not switched languages mid-run. Documented in `configuration/localization.md`, `features/settings-system.md`.
* **Correction**: locale key counts in `configuration/localization.md` and `features/settings-system.md` were stale (268 → 279 keys per locale).
* **Testing**: new unit tests `components/ErrorDialog.test.tsx` (autoplay decision failure ⇒ single Dismiss vs. generation failure ⇒ Retry), `store/gameStore.settings.test.ts` (textModel write guard), `store/gameStore.translation.test.ts` (`translationLanguageActivation` + cancel semantics); suite 324 → 336.
